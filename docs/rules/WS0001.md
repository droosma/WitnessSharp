# WS0001: Prefer `[LoggerMessage]` for `IWitness<T>` extension method logging

**Category**: Performance | **Severity**: Info | **Enabled**: Yes

## Cause

Extension methods on `IWitness<T>` that call `ILogger` methods with constant message templates incur per-call allocation and template parsing. The `[LoggerMessage]` pattern eliminates both costs. On **net9.0+**, a source-generator interceptor transparently optimizes these sites; on **net8.0**, apply the suggested code fix.

```csharp
public static void LogOrderPlaced(this IWitness<OrderService> witness, int orderId)
{
    witness.Logger.LogInformation("Order {OrderId} placed", orderId); // ⚠️ WS0001
}
```

## How to Fix

**net9.0+/net10.0**: The source-generator interceptor handles this automatically. No action needed.

**net8.0**: Apply the code-fix suggestion (or manually extract into a `[LoggerMessage]` pattern):

```csharp
public static partial class OrderServiceLog
{
    [LoggerMessage(Level = LogLevel.Information, Message = "Order {OrderId} placed")]
    static partial void LogOrderPlacedCore(ILogger logger, int orderId);

    public static void LogOrderPlaced(this IWitness<OrderService> witness, int orderId) =>
        LogOrderPlacedCore(witness.Logger, orderId);
}
```

To suppress for rare, performance-insensitive calls:

```csharp
#pragma warning disable WS0001
witness.Logger.LogInformation("Startup message {Value}", value);
#pragma warning restore WS0001
```
