# WS0001: Prefer `[LoggerMessage]` for `IWitness<T>` extension method logging

| Item        | Value                              |
|-------------|------------------------------------|
| Rule ID     | WS0001                             |
| Category    | Performance                        |
| Severity    | Info (suggestion)                  |
| Enabled     | Yes, by default                    |

## Cause

An extension method on `IWitness<T>` calls a templated `ILogger` extension method (`LogTrace`, `LogDebug`, `LogInformation`, `LogWarning`, `LogError`, `LogCritical`, or `Log`) with a constant message template. The templated methods box value-type arguments and parse the message template on every call; `[LoggerMessage]` avoids both costs, producing allocation-free, strongly-typed logging. On **net9.0+**, the source-generator interceptor rewrites these call sites automatically; on **net8.0** the code fix applies the optimization.

```csharp
public static void LogOrderPlaced(this IWitness<OrderService> witness, int orderId)
{
    witness.Logger.LogInformation("Order {OrderId} placed", orderId); // WS0001
}
```

## How to fix violations

Apply the **"Convert to [LoggerMessage] pattern"** code fix, or rewrite manually:

```csharp
public static partial class OrderServiceLog
{
    [LoggerMessage(Level = LogLevel.Information, Message = "Order {OrderId} placed")]
    static partial void LogOrderPlacedCore(ILogger logger, int orderId);

    public static void LogOrderPlaced(this IWitness<OrderService> witness, int orderId) =>
        LogOrderPlacedCore(witness.Logger, orderId);
}
```

## When to suppress

Suppress when performance is irrelevant (e.g., rare startup diagnostics):

```csharp
#pragma warning disable WS0001
witness.Logger.LogInformation("One-off startup message {Value}", value);
#pragma warning restore WS0001
```
